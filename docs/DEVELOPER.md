# Developer guide

## Build tooling

A hand-rolled Vite build (`scripts/build.mjs`) with three outputs: the popup/dashboard HTML apps, `background.js` and `content.js`.
Why not `@crxjs/vite-plugin`: `chrome.scripting.executeScript({ files: ['content.js'] })` needs a stable, self-contained classic script whose completion value is the result; a small explicit build keeps that predictable and avoids coupling to a plugin's Vite compatibility.

## Content script result

`content.js` is built as an IIFE with a footer (`content;`) so the extracted snapshot is the script's completion value, which `executeScript` returns.

## Extraction (src/content/)

- `extractor.ts` builds the `PageSnapshot`; `structured.ts` (JSON-LD, Microdata, RDFa), `network.ts` (robots.txt, sitemap) and `text.ts` are helpers. Only code under `src/content/` touches the DOM.
- Caps live in `limits.ts`. They bound snapshot size and are not scoring thresholds.
- `extractSnapshot` is async (same-origin fetches). `extractDom` is the synchronous, network-free part and is what most tests call.
- Performance note: read `document.baseURI` once, not per element (the getter is slow on large documents).

## Fixtures (tests/fixtures/)

See `tests/fixtures/README.md`. Each `<name>.html` has a `<name>.expected.json` with `snapshot` assertions (checked now) and `checks` (check ID to expected status; verified by the analyzers from Phase 4). `very-large.html` is generated by `npm run fixtures:large`, which also runs automatically before the test suite.

## How to add a check

1. Add the ID to `CHECKS` in `src/scoring/config.ts` with its category, severity and weight. Put any threshold in `THRESHOLDS` there too; analyzers contain no magic numbers.
2. Emit it from an analyzer in `src/analyzers/**` with `check(id, status, { evidence, explanation, recommendation })` from `analyzers/common.ts`. Use `notApplicable()` when the check genuinely does not apply and `notTested()` (with a reason) when the data was inaccessible. Evidence must be real extracted values.
3. Register new analyzer functions in `src/analyzers/index.ts`.
4. Add tests covering pass, warning, failure and not-applicable paths, and list the expected status in the relevant `tests/fixtures/*.expected.json`.
   The registry test fails if a configured check is never produced, or if an ID is duplicated.
